# Limitations

## Critical Non-Clinical Use Restrictions

### ⚠️ AI Output is Simulated

- The AI interpretations are generated by a **mock service**, not real ML models
- Results are **deterministic** but **not medically accurate**
- The system is designed to simulate realistic outputs for testing and demonstration only
- **DO NOT** use this system to make actual clinical decisions

### ⚠️ Not Clinically Validated

- No peer-reviewed studies validate the comparison logic
- No clinical trials compare AI predictions to pathologist gold standards
- The system has **not been approved** by any medical device authority
- No evidence that using this system improves clinical outcomes

### ⚠️ Synthetic Data Only

- All test cases use **anonymized or fully fabricated data**
- No real patient information is included
- Results seen in demos do not represent actual patient populations
- Analytics and statistics are based on seeded synthetic cases only

## Functional Limitations

### MVP Scope (Intentionally Excluded)

- ❌ **No Email Notifications**: Users must log in to check status
- ❌ **No Billing**: No payment processing or insurance integration
- ❌ **No EMR Integration**: Standalone system only; no hospital system integration
- ❌ **No Real File Storage**: Local Docker volumes only; not production-ready
- ❌ **Single Hospital**: No multi-tenant or multi-organization support
- ❌ **No Async Processing**: AI analysis runs synchronously
- ❌ **No External AI Models**: Only mock inference service
- ❌ **No Video Calling/Chat**: No real-time expert consultation
- ❌ **No Advanced Analytics**: Basic concordance and trend data only
- ❌ **No Data Anonymization Tools**: Assumes pre-anonymized input

### Known Issues

1. **No Offline Mode**: System requires live database connection
2. **Single-User Deployment**: Not tested with concurrent users
3. **No Rate Limiting**: Could be abused with rapid requests
4. **Limited UI Responsiveness**: Not optimized for slow networks
5. **No Backup Strategy**: Local data loss if Docker volume deleted
6. **No Automatic Scaling**: Fixed container resources

## Security Limitations

See `docs/privacy-and-security.md` for detailed gaps. Key points:

- ❌ No encryption at rest
- ❌ No encryption in transit (HTTP only in dev)
- ❌ No multi-factor authentication
- ❌ No formal penetration testing
- ❌ No intrusion detection
- ❌ No formal access logging review process
- ❌ JWT tokens in plain environment variables
- ❌ Single shared secret key for all deployments (unsafe for production)

## Data & Compliance Limitations

### Privacy

- MVP assumes data already de-identified
- No automated de-identification or masking
- No data residency enforcement (not geo-fenced)
- No compliance with PHIPA, HIPAA, GDPR beyond documentation
- No formal Data Processing Agreement (DPA)

### Audit Trail

- Audit logs stored in same database (could be compromised together)
- No tamper detection
- No long-term immutable archive
- Logs deleted if database dropped

### Data Retention

- No automatic cleanup of old data
- No retention policy enforcement
- No secure deletion (only database DELETE)

## Performance Limitations

- Synchronous AI analysis blocks UI during processing
- No caching of comparison results
- No pagination optimization for large datasets
- Reports generated on-demand (not pre-computed)
- No query result caching

## Integration Limitations

- ❌ Cannot ingest HL7/FHIR standards
- ❌ No DICOM support for ECG images
- ❌ No integration with lab systems
- ❌ No integration with EHR systems
- ❌ No fast healthcare interoperability resources (FHIR)
- ❌ Cannot export to common formats beyond JSON/CSV

## Platform Support

- **Tested On**: macOS, Linux (Docker)
- **Browsers**: Chrome, Safari, Firefox (modern versions)
- **Not Tested**: Mobile devices, older browsers, Windows Subsystem for Linux

## Scalability

The MVP is designed for **small pilot testing only**:
- ~100 concurrent users maximum
- ~1,000 cases maximum
- Single database instance
- No load balancing
- No read replicas

For production with >100 users:
- ✅ Horizontal scaling with load balancer
- ✅ Database read replicas
- ✅ Redis for caching
- ✅ Message queue for async tasks
- ✅ CDN for static assets
- ✅ S3 for file storage

## Testing Coverage

- ❌ No end-to-end (E2E) tests in MVP
- ✅ Basic unit tests for core logic
- ✅ API endpoint tests
- ⚠️ Frontend component tests (minimal)
- ❌ Load testing not done
- ❌ Security testing not done
